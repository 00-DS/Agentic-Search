# Agentic Search with Memory — 项目概览

## 项目概述

Python 与原生 HTML/JavaScript 从零构建一个**带记忆的论文问答助手**。它的核心闭环是——上传论文 PDF → AI 阅读论文并以流式方式回答问题 → 记住研究方向，在后续对话中复用已记住的事实。

整个系统由两个独立部分组成：

- **后端服务**（`backend/`，FastAPI）：负责全部业务逻辑——PDF 解析、LangGraph Agent 工作流、TMT 记忆系统、4 个 HTTP API 端点。
- **前端**（`frontend/`）：两个纯静态文件（`index.html` + `app.js`），只负责界面与网络通信，通过浏览器原生的 `fetch` API 与后端通信，**无任何构建步骤**。

项目保持两层架构（前端静态文件 + 后端 FastAPI），把学习注意力集中在 Python 业务逻辑与 Agent 工作流本身。

## 系统架构

系统采用两层架构：前端与后端是两个并列的独立服务，职责解耦。前端只处理界面与网络请求，后端只处理业务逻辑。

```
agentic-search/
│
├── frontend/（前端，:3000）
│   ├── index.html          # 页面结构
│   ├── app.js              # fetch + DOM + 流式读取
│   └── ──fetch──→ backend :8000（跨服务 AJAX）
│
└── backend/（FastAPI API 服务，:8000）
    │   configs/config.py     # 配置（.env）
    │   api/routes.py       # 路由：query / ingest / documents / consolidate
    ├─ ReAct Agent        # agents/graph.py（llm_call ⇄ tool_node + 条件边）
│   └─ TMT 记忆             # memory/memory.py（加工）+ memory/db.py（数据库操作）
```

**两个独立服务，职责解耦**：

- **前端**：纯静态文件（`index.html` + `app.js`），浏览器直接打开，或由 `python -m http.server` 托管。无构建步骤。
- **API 服务**：FastAPI 运行在 `:8000`，只负责把 Python 逻辑包装成 HTTP 接口，不碰静态文件。

**CORS 处理**：前端与后端分属不同端口（`:3000` 与 `:8000`），属于跨源请求。后端在 `main.py` 中加入 CORS 中间件放行跨源请求：

```python
from fastapi.middleware.cors import CORSMiddleware
app.add_middleware(CORSMiddleware, allow_origins=["*"], allow_methods=["*"], allow_headers=["*"])
```

**开发流程**：

```bash
# 后端（uv 安装依赖并以 uvicorn 启动）
cd backend && uv sync && uv run uvicorn agentic_search.main:app --reload --port 8000

# 前端（二选一）
#   方式 1：浏览器直接打开 frontend/index.html
#   方式 2：cd frontend && python -m http.server 3000 → 访问 http://localhost:3000
```

## 文件结构

整个项目的完整目录树如下。后端采用**包化布局**（`backend/src/agentic_search/`），分层清晰、职责单一；前端只有两个文件。

```
agentic-search/
├── backend/
│   ├── pyproject.toml              # name="agentic_search"，包可安装
│   ├── .env.example                # 配置模板（LLM 模型名、超时、MongoDB 连接）
│   ├── src/agentic_search/         # 包化布局（import: from agentic_search.agents.graph import ...）
│   │   ├── __init__.py
│   │   ├── main.py                 # 瘦入口：仅创建 FastAPI app + 挂路由 + CORS
│   │   ├── configs/
│   │   │   └── config.py           # 配置（从 .env 读：超时、MongoDB URI/库名、LLM 模型名）
│   │   ├── api/
│   │   │   ├── routes.py           # 路由：query/ingest/documents/consolidate
│   │   │   └── schemas.py          # 请求/响应 Pydantic 模型
│   │   ├── agents/
│   │   │   ├── tools.py            # 论文导航工具（list_papers/read_paper/search_paper/extract_abstract，模块 1）
│   │   │   └── graph.py            # LangGraph ReAct agent（llm_call ⇄ tool_node + 条件边，模块 2）
│   │   ├── memory/
│   │   │   ├── memory.py           # TMT 记忆加工（L1/L2/L5 提取/整合）
│   │   │   └── db.py               # TMT 记忆数据库操作（MongoDB 读写 + 注入取数）
│   │   └── services/
│   │       └── documents.py        # 文档工具（parse_pdf / store / list / read_lines / search_doc / get_abstract）
│   │   # 数据全部存入 MongoDB（不落盘）：
│   #   · agentic_search.memories  → L1/L2/L5 记忆
│   │   #   · agentic_search.documents → 论文完整文本
│   └── tests/
│       ├── test_documents.py
│       ├── test_graph.py
│       └── test_memory.py
│
├── frontend/
│   ├── index.html                # 页面结构（原生 HTML，无样式）
│   └── app.js                    # 逻辑（fetch + DOM 操作）
│
└── AGENTS.md
```

**各层职责一览**（架构中的位置）：

- `main.py` — 瘦入口，只创建 app、挂路由、配 CORS，不含业务逻辑。
- `configs/config.py` — 配置层，从 `.env` 读 LLM 模型名、超时、MongoDB URI 与库名。
- `api/` — HTTP 层（`routes.py` 路由 + `schemas.py` 请求/响应模型），不碰 LLM/文档细节。
- `agents/tools.py` — 论文导航工具（`list_papers`/`read_paper`/`search_paper`/`extract_abstract`），用 LangChain `@tool` 声明——薄委托，逻辑在 `services/documents.py`。
- `agents/graph.py` — LangGraph ReAct agent：`llm_call ⇄ tool_node` 循环，条件边 `should_continue` 控制继续/终止，`bind_tools` 绑定 `tools.py` 的四个导航工具。
- `services/documents.py` — 文档工具（`parse_pdf` / `store_doc` / `list_docs` / `read_lines` / `search_doc` / `get_abstract`）。
- `memory/memory.py` — TMT 记忆加工（L1 事实提取 + L2 会话整合 + L5 用户画像）；`memory/db.py` — 数据库操作（Memory + MongoDB 读写 + 幂等写入 + 注入取数）。

系统直接运行，不需要额外的运行时环境。

## 模块设计

项目按职责拆分为 4 个模块。每个模块都有明确的可验证产出。

### M1：Python 文档工具

**学习目标**：Python 包化布局（src layout）、pydantic-settings 配置层、pymupdf PDF 转纯文本、PyMongo 存取、LangChain `@tool` 装饰器。

内容：

1. **pyproject.toml + 包化布局** — `uv sync` 后即可 `from agentic_search.services.documents import ...`。
2. **configs/config.py** — pydantic-settings 从 `.env` 读 LLM 模型名、MongoDB 连接配置。
3. **services/documents.py** — `parse_pdf()` 用 pymupdf 的 `get_text("text")` 把 PDF 转为完整纯文本后存入 MongoDB、`list_docs()` 查询集合。
4. **agents/tools.py** — 论文导航工具集：用 LangChain `@tool` 声明四个工具（`list_papers`/`read_paper`/`search_paper`/`extract_abstract`），从类型注解 + docstring 自动生成工具 schema。
5. **pytest 测试**（`test_documents`）。

**产出**：包化地基 + 文档工具（PDF 提取纯文本）+ 论文导航工具（4 个 `@tool`）。

### M2：LangGraph Agent

**学习目标**：LangGraph ReAct agent（工具调用 + 条件边）、自定义装饰器（`@retry`）、FastAPI 分层 API（`@router.post`）、CORS。

内容：

1. **agents/graph.py** — LangGraph ReAct agent：`llm_call ⇄ tool_node` 循环 + 条件边，`bind_tools` 绑定 `tools.py` 的四个工具，LLM 自主调用探索论文。
2. **api/routes.py + api/schemas.py** — 4 个端点 + Pydantic 请求/响应模型。
3. **main.py** — 创建 app，挂载 routes，配置 CORS。
4. **pytest 测试**（`test_graph`）。

**产出**：LangGraph Agent 工作流 + 4 个 API 端点。

### M3：HTML 前端

**学习目标**：HTML 结构、fetch API、DOM 操作、流式响应。

内容：

1. **index.html** — 页面结构（垂直单页布局：控件区 → 消息区 → 输入区，无 CSS，浏览器默认样式）。
2. **app.js** — `fetch` 上传文件、`fetch` 提问、流式读取 `ReadableStream`、DOM 渲染。核心函数约 80 行：`uploadFile()` / `askQuestion()` / `appendMessage()` / `consolidateMemory()`。（文档列表已交给后端 agent 的 `list_papers` 工具，前端不再渲染下拉框。）
3. 无构建步骤，直接浏览器打开或 `http.server` 托管。

**产出**：`index.html` + `app.js`，可上传 PDF、提问、流式渲染回答。

### M4：记忆系统

**学习目标**：TMT 记忆思想（L1 事实提取 + L2/L5 整合）、MongoDB 持久化。

内容：

1. **memory/memory.py** — L1 事实提取、L2 会话摘要、L5 画像整合（LLM 加工，纯进出）。
2. **memory/db.py** — 数据库操作（Memory + MongoDB 读写 + 幂等写入 + 注入取数，含 L2 阈值自动触发的常量）。
3. 集成到 LangGraph 图（`retrieve_memory` + `store_memory` 节点）。
4. 前端展示记忆状态（可选）。

**产出**：`memory/memory.py` + `memory/db.py`，实现 L1 事实提取（每轮自动）+ L2 会话整合（阈值自动 + 手动触发）。

**模块依赖关系**：M1 是后端地基（文档处理 + 导航工具），M2 在此之上组装 Agent 并暴露 API（依赖 M1 的工具），M3 是展示与交互层（依赖 M2 的端点），M4 给 Agent 注入记忆能力（嵌在 M2 的 LangGraph 图中）。建议的学习顺序是 M1 → M2 → M3 → M4。

## API 设计

后端通过 FastAPI 暴露 4 个端点，覆盖上传、提问、查询、记忆整合四个动作：

| 方法 | 路径 | 功能 | 请求体 | 响应 |
|------|------|------|--------|------|
| POST | `/api/query` | 向 Agent 提问 | `{"question": "..."}` | SSE 流式文本 |
| POST | `/api/ingest` | 上传 PDF | `multipart/form-data`（文件） | `{"doc_id": "...", "filename": "..."}` |
| GET | `/api/documents` | 列出已上传文档 | 无 | `[{"doc_id": "...", "filename": "..."}]` |
| POST | `/api/consolidate` | 手动触发 L2 整合 | `{"session_id": "..."}` | `{"status": "ok", "l2_id": "..."}` |

**前端调用示例**（`app.js`）：

```javascript
// 上传 PDF
const form = new FormData();
form.append('file', fileInput.files[0]);
const res = await fetch('http://localhost:8000/api/ingest', { method: 'POST', body: form });
const { doc_id } = await res.json();

// 提问（流式）
const res = await fetch('http://localhost:8000/api/query', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ question: '这篇论文的主要贡献是什么？' })
});
const reader = res.body.getReader();
const decoder = new TextDecoder();
while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  appendToLastMessage(decoder.decode(value));  // 逐块显示
}
```

## 数据流

### 上传 PDF 流程

```
浏览器 app.js
  │ FormData + fetch POST /api/ingest
  ▼
FastAPI api/routes.py
  │ 接收 PDF（内存中，不落盘）
  ▼
pymupdf get_text("text") → 完整纯文本（内存中处理，不落盘）
  │
  ▼
存入 MongoDB documents 集合 {doc_id, filename, text: 完整纯文本, uploaded_at}
  │ 返回 {doc_id, filename}
  ▼
浏览器收到响应，更新文档列表
```

### 提问流程

```
浏览器 app.js
  │ fetch POST /api/query {question}
  ▼
FastAPI api/routes.py → StreamingResponse
  ▼
LangGraph ReAct agent
  ├─ retrieve_memory: 取 L1/L2/L5 记忆（M4 加入）
  ├─ [ llm_call ⇄ tool_node ]：LLM 自主调 list_papers / read_paper / search_paper / extract_abstract 探索论文
  └─ store_memory: 提取事实存入记忆（M4 加入）
  │ 流式输出 tokens
  ▼
浏览器 ReadableStream 逐块显示
```

### 记忆流（M4）

```
L1（每轮对话后自动触发）：
  LLM 从对话提取原子事实 → 写入 MongoDB memories 集合

L2（阈值自动触发 + 按钮兜底，便于教学测试与展示）：
  store_memory 节点检测新增 L1 ≥ 10 → 图内联自动重新整合
  兜底：用户点击「整合会话记忆」按钮 → POST /api/consolidate
  LLM 整合该会话所有 L1 → L2 会话摘要
  幂等：同一会话最多一个 L2，已有则增量更新
  写入 MongoDB memories 集合

下次提问时：
  retrieve_memory 注入 L5 画像与本会话 L1/L2（配额注入）
```

**L2 触发机制说明**：TiMem 生产实现中（源码 `services/session_memory_scanner.py`），L2 由 `SessionMemoryScanner` 定期扫描，当会话**最后一次交互超过配置超时**（默认 `interaction_timeout_minutes=10`，即 10 分钟无交互）时视为会话已结束并触发 L2 生成。但教学项目为了便于测试和演示，不等待 10 分钟空闲，改为**阈值自动触发**（新增 L1 ≥ 10 时图节点内联重新整合）+ **前端按钮「整合会话记忆」兜底**（`POST /api/consolidate`）；TiMem 的空闲超时原理仍作为背景概念讲解。

## 技术栈

| 技术 | 角色 | 文件 |
|------|------|------|
| Python 3.11+ | 文档工具 + Agent + 记忆 | backend/ |
| uv | Python 包管理 + 可安装包 | pyproject.toml |
| pymupdf | PDF → 纯文本提取（`get_text("text")`） | services/documents.py |

| FastAPI + uvicorn | Python API 服务（ASGI） | api/routes.py, main.py |
| Pydantic | 请求/响应数据模型 | api/schemas.py |
| MongoDB | 记忆数据 + 论文文档存储 | agentic_search（localhost:27017） |
| PyMongo | MongoDB Python 驱动（同步） | memory/db.py, services/documents.py |
| MongoDB Compass | 数据库可视化工具（教学调试） | — |
| pytest | Python 测试 | tests/ |
| 原生 HTML + JS（fetch） | 前端界面与 AJAX 通信 | frontend/ |

## 面向学生

面向具备基本编程概念与命令行操作能力的初学者，从零起步。

前置要求：

- 一个可用的 LLM API Key
- 安装 [uv](https://uv.oaix.tech/)（Python 包管理器，统一负责依赖安装与运行）
- 安装 [MongoDB Community Server](https://www.mongodb.com/try/download/community)（localhost:27017，记忆与文档数据的唯一存储）
- 安装 [MongoDB Compass](https://www.mongodb.com/products/tools/compass)（数据库可视化工具，教学调试用）
- 一个现代浏览器（用于打开前端、与后端通信）
